# MiNi Payment Server — task backlog

Evidence-based backlog. A task is **Done** only when its verification evidence is recorded below with the commands actually run. Priorities: P0 = required for the first end-to-end sandbox payment, P1 = core product, P2 = product completeness, P3 = learning/optional. Status values: `Done`, `Ready` (dependencies met), `Blocked`, `Planned`.

Delivery order follows the master prompt: foundation → auth → ledger/payments → real-time → remaining modules. The first end-to-end milestone (**M1**) is: register → login → sandbox-funded wallet → create + authorize payment → ledger updated → Socket.IO event → transaction visible in history.
